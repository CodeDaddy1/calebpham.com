A recorded composition cannot read a CSS variable. If it needs the site's colours it has to carry a copy of them, and a copy falls behind the moment the original moves.

## The decision

LumaIQ's landing page plays two short product films. They are compositions rendered by a small runtime, and they hardcode the light palette so the film does not follow the viewer's theme. That is correct: a recording that changed colour with the OS setting would be a different film for every viewer. But it means the scenes hold literal hex values that the token file no longer knows about.

So the contrast test reads the scene files, finds each frozen value by name, and compares it to the live token. A palette change that is not re-synced into the scenes is a red test, not a silent drift.

<CodeQuote file="src/app/globals.contrast.test.ts" lines="173 to 211">

```ts
describe('film scenes keep their frozen palette in sync', () => {
  // showcase-scene.tsx and three-jobs-scene.tsx hardcode a copy of the light
  // palette so the recorded video does not follow the viewer's theme. That is
  // correct, but it means they silently fall behind globals.css — and because
  // both scenes also render on the live landing page, falling behind puts
  // unreadable copy in front of real visitors. It already happened once: the
  // frozen values stayed at the pre-AA palette and a rendered-DOM sweep of `/`
  // found 72 strings under 4.5:1, every one of them from these two files.
  const light = tokenBlock(':root')
  const strip = (s: string) => s.replace(/\s+/g, '')

  const EXPECTED: [string, string][] = [
    ['muted', light['--muted']],
    ['mutedStrong', light['--muted-strong']],
    ['accent', light['--accent']],
    ['warning', light['--warning']],
    ['danger', light['--danger']],
    ['info', light['--info']],
  ]

  const SCENES = ['showcase-scene', 'three-jobs-scene']

  describe.each(SCENES)('%s.tsx', scene => {
    const src = readFileSync(
      fileURLToPath(new URL(`../app/(marketing)/_components/film/${scene}.tsx`, import.meta.url)),
      'utf-8',
    )

    for (const [key, tokenValue] of EXPECTED) {
      it(`${key} matches the token`, () => {
        const m = src.match(new RegExp(`\\b${key}:\\s*'([^']+)'`))
        expect(m, `${scene}.tsx has no \`${key}\` in its frozen palette`).toBeTruthy()
        expect(
          strip(m![1]),
          `${scene}.tsx ${key} is ${m![1]} but the token is ${tokenValue} — re-sync the frozen palette`,
        ).toBe(strip(tokenValue))
      })
    }
  })
```

</CodeQuote>

## The measurement

It had already gone wrong once. After an accessibility pass moved the palette, the frozen values stayed at the old one, and a sweep of the rendered landing page found 72 strings under 4.5 to 1, every one of them from the two scene files. The pass had made the product readable and left its own advertisement unreadable, on the page that makes the first impression.

The same shape recurs anywhere a value is copied out of the token layer on purpose: the social card this site generates holds its own literals for the same reason, and the same kind of test pins them to the tokens.

## What breaks if this is wrong

The product is fixed and the page selling it is not. Nobody who works in the product sees the landing page often enough to notice, and the visitor who does notice does not report it. They leave.
